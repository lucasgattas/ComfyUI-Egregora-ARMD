# Architecture Notes

## Purpose

Egregora-ARMD applies region-based diffusion to ComfyUI workflows by splitting a latent canvas into planned regions, denoising those regions in controlled batches, and blending the resulting outputs back into a shared latent canvas.

The implementation is designed around a few principles:

- region planning should be explicit and deterministic;
- runtime batching should be independent from prompt authoring;
- payload routing should work with tensors and static objects without hard-coding workflow-specific assumptions;
- blending should remain stable across overlaps and batch sizes;
- ControlNet integration should accept already-prepared runtime payloads instead of mutating internal control objects.

## Core building blocks

### 1. Region planning

`RegionPlan` and `RegionBBox` define the canonical geometry for the run:

- aligned canvas size;
- latent size;
- compression factor;
- region size and overlap;
- latent-space and pixel-space bounding boxes.

This planning step ensures every later stage operates on a known spatial contract.

### 2. Spatial adapters

The package separates runtime inputs into adapters so the denoising wrapper can consume multiple data shapes consistently:

- packed spatial tensor adapters for image- or latent-like payloads;
- static object adapters for non-spatial runtime payloads;
- merged runtime adapters when multiple payload groups must travel together.

This keeps routing generic and avoids hard-wired assumptions about one specific workflow layout.

### 3. Regional conditioning

Regional positive and negative conditioning is normalized into batches with aligned sequence lengths. Cross-attention payloads are repeated or reshaped only as needed to satisfy the model-side batch contract.

### 4. Runtime batching

The latent canvas is sliced into region batches according to `region_batch_size`. Each batch is denoised independently and then accumulated back into a shared canvas.

This allows the node to trade memory usage against throughput while preserving deterministic region layout.

### 5. Overlap blending

Blending uses a linear ramp weight map generated by `build_bbox_blend_weight(...)`.

The ramp strategy provides a simple and inspectable overlap behavior:

- full weight in the core of a region;
- smooth attenuation near borders that participate in overlaps;
- normalization through a dedicated weight accumulator.

This keeps the blend path explicit and easy to reason about during debugging.

### 6. ControlNet/runtime payload handling

The ControlNet-oriented path is designed to consume precomputed runtime payloads, especially tensor payloads already prepared by compatible upstream workflow components.

The goal is to keep the ARMD wrapper focused on spatial slicing and batch orchestration rather than depending on private internal mutation of external control objects.

## Design boundaries

The package intentionally draws a boundary between:

- **planning**: geometry, alignment, overlap, region count;
- **conditioning**: prompt/cross-attention organization;
- **payload transport**: images, latents, control-like tensors, static objects;
- **execution**: per-region denoising;
- **reconstruction**: weighted accumulation back into the latent canvas.

That separation helps the code remain easier to test, extend, and reason about.

## Current publication posture

At this stage, the package is ready for deeper validation with real workflows. Before broad release, the main remaining work should focus on:

- stress-testing across SD 1.5, SDXL, and Z-Image-style pipelines;
- verifying adapter behavior with real Advanced-ControlNet payloads;
- benchmarking seam quality and overlap settings;
- adding sample workflows and usage documentation.
